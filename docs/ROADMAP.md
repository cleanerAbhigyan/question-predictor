# Evidence-gated roadmap

As of 2026-11-14, Phase 0 foundation and Phase 1A metadata discovery/tooling are implemented. The wider Phase 1 audit still needs actual permitted document evidence, with no real paper acquired or approved. Later work requires a newly published [current task](CODEX_NEXT_TASK.md); Phase 1B and phases 2–7 have not started. Development phases below are distinct from exam Phase I/II.

| Phase | Scope and dependencies | Verifiable exit gate | Status |
| --- | --- | --- | --- |
| 0 — Foundation | Safely sync persistent `feature`; document boundaries, schema proposals, source verification, blind backtests and future export | Required docs/links/statuses checked; ignore behavior and public-content review passed; actual check evidence recorded in [development log](DEVELOPMENT_LOG.md); commit/push/PR and latest-head CI reported in handoff | Completed — documentation only |
| 1 — Source audit | Depends on Phase 0 and a published task; discover actual candidate papers and rights, establish scope | Reviewable source registry with publisher/date/URL/hash where acquired, independent identity/readability/rights/completeness assertions, conflicts and explicit missingness; no fabricated coverage | Phase 1A implemented; document acquisition/review pending |
| 2 — Normalization and verification | Depends on usable permitted sources from Phase 1; implement/test versioned contracts and extraction only as tasked | Source-linked questions and answer evidence pass actual validators/review; stable IDs, rejected examples, auditable corrections and exclusions; permitted corpus manifest frozen | Not started |
| 3 — Taxonomy and descriptive analytics | Depends on Phase 2 reviewed observations; isolate Phase I sections and Phase II papers | Versioned reviewed topic annotations and reproducible observed counts with question IDs, denominators, partial-paper limitations and repeat distinctions; no invented patterns | Not started |
| 4 — Frozen baselines and backtest harness | Depends on Phase 3 and sufficient real training/held-out material | Tested deterministic baselines and scoring, access isolation, publication cutoffs, lock receipts/hashes and reproducible per-paper results; failures/non-blind runs disclosed | Not started |
| 5 — Model-assisted research | Depends on Phase 4 evidence and a scoped model task; no assumption that models improve baselines | Frozen model configurations/prompts, actual blind/retrospective classifications, baseline comparisons, misses/false positives and contamination limits; no accuracy target assumed | Not started |
| 6 — Original practice and review | Depends on research validation in Phase 5; stage generated questions with explicit labels | Originality, answer/rubric, provenance, scoring and rights reviewed; immutable human approval, model/run IDs and limitations; no generated content treated as PYQs | Not started |
| 7 — Approved offline export | Depends on Phase 6 for generated sets, approved eligible content and separate contract approval by both repositories | Implemented/tested versioned producer/consumer in separately authorized tasks; rejection, checksums, idempotency, revocations and approval gates verified end to end; reviewed offline transfer only | Not started |

Dependencies do not promise usable sources or successful predictions. If data is too thin, document the evidence gap and stop the affected work rather than creating scores. Earlier reviewed historical PYQs can be considered by the independent simulator through its own tasks; this roadmap does not impose predictor model development on it.

Phase 1A delivers the offline registry/validator/audit, private opt-in checksum receipts, 16-slot blank-page audit, six landing-page leads, acquisition guide and tests/CI. See the [development log](DEVELOPMENT_LOG.md) for actual checks and the [report](SOURCE_AUDIT_REPORT.md) for unresolved evidence. These are not authenticated papers, answer keys or whole-exam coverage. Do not auto-start Phase 1B.

No phase confirms 2027 dates, eligibility, pattern or marking; these require official notice evidence. Maintain the Govt study allocation of 60% common banking / 40% RBI-specific when planning study, and never count repository research as study completion or mock attempts. Keep the single `feature` PR updated without force-push or merge, and preserve independent repository boundaries throughout.
