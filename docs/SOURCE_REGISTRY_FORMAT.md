# Implemented Phase 1A metadata format 1.0.0

The executable contract is [records.py](../predictor/records.py), with [private receipt validation](../predictor/acquisition.py). JSON files carry `schema_version: 1.0.0`; unsupported versions, extra/missing fields, duplicate JSON keys, malformed types, invalid dates and unresolved evidence fail the entire operation. This is a small standard-library validator, not a generic JSON Schema implementation. The [future research contracts](DATA_SCHEMA.md) remain proposed beyond this subset.

## Public registry

The exact top-level keys are `schema_version`, `as_of`, `candidates`, `slots`, `ledger`. The checked-in [registry](../registry/sources.json) is the authoritative metadata input. The CLI only reads it; editing a source observation requires an explicitly reviewed metadata change and a new candidate revision. There is no live scraping or append operation. Keep prior revisions in Git and do not regenerate IDs from a renamed title or changed URL.

| Record | Exact fields and interpretation |
| --- | --- |
| Candidate | `candidate_id`, `revision`, `example_only`, `title`, `provider`, `landing_url`, `content_kind`, `source_category`, `authentication_status`, `readability_status`, `completeness_status`, `answer_status`, `review_status`, `access_state`, `discoverability`, `published_on`, `answer_key`, `content_hash`, `paper_identity`, `missing_reasons`, `rights`, `claims`, `evidence_refs`, `unresolved` |
| Paper research slot | `slot_id`, `revision`, `year`, `phase`, `notion_url`, `access_state`, `exam_occurrence`, `missing_reasons`, `evidence_refs`. A slot is not an ExamPaper and is not proof an exam occurred. Omitted slots are reported as not audited. |
| Ledger event | `event_id`, `subject_id`, `subject_revision`, `source_url`, `assessed_at`, `assessor`, `summary`, `source_category`, `claims`, `published_on`, `rights`, `access_state`. Record the actual source of an assertion; agent metadata observations do not constitute human paper approval. |
| Attributed claim | `year`, `phase`, `paper`, `session`, `missing_reasons`, `evidence_refs`. Candidate claims must exactly match a referenced event claim; event claims have an empty reference list to avoid circular evidence. |
| Per-action right | `status`, `missing_reason`, `evidence_refs`, under exactly `acquisition`, `personal_analysis`, `quotation`, `model_ingestion`, `public_redistribution`. A known status requires matching scoped ledger evidence from a human metadata reviewer. Unknown rights authorize nothing. |

Candidate/slot/event IDs use `cand-`, `slot-`, `ev-` plus opaque UUIDs; positive integer revisions exclude booleans. Seed inventory IDs were allocated once with UUID5 from non-personal inventory keys and are now immutable. They are distinct from future acquired `src-` IDs. URLs are references, not identity keys. Test fixtures use reserved `EXAMPLE-` IDs and artificial provider domains; the public CLI rejects them. Internal test-only keyword options do not enable approval or historical-PYQ admission.

`missing_reasons` must contain exactly the fields whose required values are null: candidate provider/publication/key/hash/paper identity, claim year/phase/paper/session, or slot exam occurrence. Reasons are `not_provided`, `not_checked`, `not_acquired`, `unverified`, `not_applicable`, `conflicting`. Null means unknown, not zero/false; absent fields are invalid. Empty claim arrays mean no attributed claims have been recorded. Publication dates, when evidenced, must be real `YYYY-MM-DD` dates no later than their assessment; assessment/as-of/receipt timestamps use second-precision UTC with `Z`. A timestamp records the observation, not the source's publication date.

Phase is `I` or `II`. Paper names are Phase I `GA`, `English`, `Quant`, `Reasoning`; Phase II `ESI`, `FM`, `English Writing`. `combined` is a collection-level lead, not proof of component availability. Sessions may be `shift_1`, `shift_2` or unknown with a reason; no new shift is inferred. The supported slot interval is 2018–2025, including an unverified 2020 research slot. Claims outside that interval can be kept as attributed archival metadata but are not scored as modern availability.

Public HTTPS URLs exclude credentials, nonpublic literal IPs, fragments, percent-encoded paths and queries; only the RBI legacy `Id=<digits>` query is allowed. Descriptive text is bounded, single-line and rejects common private-path/secret patterns and markup. These checks cannot determine copyright or prove an arbitrary sentence contains no personal/question text: human review remains mandatory before publication.

The independent category values are `official`, `memory_based`, `coaching_reconstruction`, `unverified`, `model_generated`. `official` on the two inspected RBI HTML references applies to the landing pages only. The public model accepts `unreviewed`/`disputed`/`rejected` authentication, `unreviewed`/`not_accessible` source readability, `unknown` completeness/answers, and `pending`/`rejected` review. Known allowed/prohibited/restricted rights remain separate assertions. It rejects acquired, readable, partial, verified, reviewed or approved **paper** states because this milestone stores no document evidence/receipts in the public registry. A later schema/task is required to admit those states; metadata review never fabricates such evidence.

Candidate access is `access_not_checked`, `landing_read` or `access_blocked`; discoverability is `lead_only`, `links_advertised` or `login_required`. Source readability is intentionally separate from landing-page accessibility. Slots record `not_audited`, `checked_blank`, `checked_content`, `not_checked_access_unavailable`. A nonblank page alone does not promote any paper. Evidence references resolve to immutable event IDs that pin the exact subject ID and revision, plus the registry snapshot and Git commit.

## Audit output

JSON and Markdown outputs use fixed year/phase/paper ordering, sorted candidate IDs and unresolved gaps, and the registry's stored as-of time rather than the execution clock. The 56 component cells retain independent Notion access, source-lead IDs and unknown exam occurrence. An absent slot yields `not_audited`; a checked blank slot without a lead yields `missing`; an access failure without a lead yields `not_accessible`. A supported collection claim yields `lead_found`, which does not override blank Notion evidence or imply readable content. No `partial` or `reviewed` paper status is emitted without document evidence; this version deliberately cannot approve a paper. Counts describe this public registry only, not private files a user may hold.

Generated and sample-reference candidates are excluded from historical lead matching, even if they carry year claims. The generated [Markdown](SOURCE_AUDIT_REPORT.md) and [JSON](../registry/audit.json) reports are checked against regeneration in tests and CI. Provider snippets are short attributed metadata summaries, not stored article/paper text. The research protocol's authentication, correctness and legal-use assertions remain independent.

## Private acquisition receipt

The exact envelope is `schema_version`, `acquisitions`. Each receipt has `acquisition_id`, `source_id`, `candidate_id`, `candidate_revision`, `sha256`, `byte_size`, `media_type`, `registered_at`, `assessor`, `permission_reference`, `rights_cleared`. No path, filename, document contents or public source-authentication claim is stored. IDs are deterministically allocated from the private digest and explicit acquisition context so identical invocations are reproducible; they must remain private. Duplicate acquisition/source IDs in a receipt batch are rejected. A source UUID identifies hashed bytes, not a verified publisher or licensed historical paper.

Only an explicit `register-local` call reads raw bytes, after requiring the candidate reference, timestamp, non-personal reviewer, permission reference and affirmative acquisition/personal-analysis clearance. Known restrictions cannot be overridden. This attestation is not independent legal verification and grants no model-ingestion or publication permission. Dry-run is default; deliberate saves only create new mode-0600 receipt files under ignored `data/private/`, atomically and without overwrites. A file signature is not full PDF validation. See the [acquisition guide](SOURCE_ACQUISITION_GUIDE.md).
